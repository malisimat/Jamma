## Blocking finding

### B009-R1 — required callback benchmark is absent

`cleanup-backlog.md` specifies “one calculation per block and callback benchmark” as B009 verification. The F-006 row in `verification-matrix.md` is more specific: the manual/stress obligation is a maximum-hierarchy callback benchmark. The implementation record instead states that no profiler/maximum-hierarchy callback benchmark was available and treats repeated focused tests as a non-gating proxy.

That substitution is insufficient. The static call-chain audit does establish that production has exactly one `SyncPhaseMap::SourceCoordinateAt` call in AudioHost and none in Station/LoopTake, independent of take count. It does not measure the callback cost of the new common-coordinate fan-out at the maximum configured station/take/loop hierarchy, nor compare the relevant callback path before and after consolidation. P3/P4 repetitions establish determinism and correctness, not callback duration.

Required correction: within B009's existing test/verification boundary, run and record a reproducible callback-path benchmark at the maximum configured hierarchy size, including the exact harness/scenario, configuration, block size, hierarchy cardinalities, iteration/warm-up counts, timing statistic(s), and acceptance/comparison criterion. The evidence must demonstrate that callback cost remains bounded while the common mapping calculation count is independent of take count. If a small test-only harness or instrumentation is necessary, keep it in B009-owned focused test files, add no production logging/allocation/lock or public test API, and preserve the private friend-only AudioHost boundary. Re-run the required focused verification, reconcile the canonical artifacts so they no longer defer this B009 gate to Stage 21, and obtain a superseding independent approval before B010.
