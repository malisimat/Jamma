Local Loop Alignment

This is the calculation that lets a scene of differently sized local loops stay phase-related. It is written for investigating the specific failure mode where a NINJAM transport change leaves local loops mutually displaced.

Where The Clock Lives

utils::Timer is the scene's master transport. It owns LoopCount, SampOffset, and the seeded master length M. Its absolute position is:

A = LoopCount * M + SampOffset

It advances in Timer::Tick. A local audio loop owns only its own wrapped playback cursor in engine::Loop::_playIndex. The cursor advances in Loop::EndMultiPlay. A loop take does not have an independent master counter in the current runtime model.

The Alignment Calculation

There is no universal zero-origin phase. Audio playback includes a storage-only fade prefix and MIDI playback does not, so each playable loop needs its own master-relative anchor.

audioPhase_i = normalize(rawPlayIndex - MaxLoopFadeSamps, L_i)
midiPhase_j  = midiPlayIndex mod L_j
masterAnchor_k = normalize(masterAbsolute - localPhase_k, L_k)

At any later master position A', restore the local cursor exactly with:

localPhase_k = normalize(A' - masterAnchor_k, L_k)

For audio, convert that body phase back to the fade-prefixed storage cursor before calling the audio-loop restore path. For MIDI, use the phase directly; no fade subtraction or addition applies. A pair of loops is relatively aligned when each is restored from its own captured masterAnchor against the same A'.

Grain Constraint

With local grain G, a clean quantized loop has L_i mod G = 0. The diagnostic prints both grains = L_i / G and grainRemainder = L_i mod G. A nonzero remainder means that grid recovery can only be approximate unless the loop is resized or a different grain is selected.

Console Snapshots

Station::_LogLocalLoopAlignment emits one header and one row per local audio and MIDI loop immediately after record or overdub finalization, and immediately before deletion. The output is deliberately stable and grep-friendly:

[LocalLoopAlignment] event=recorded ... masterLength=... masterCycle=... masterOffset=... masterAbsolute=... grain=...
[LocalLoopAlignment] take=... loop=... length=... rawIndex=... musicalIndex=... masterAnchor=... localCycle=... grains=... grainRemainder=...
[LocalLoopAlignment] take=... midiLoop=1 length=... midiCursor=... masterAnchor=... automationAnchor=... automationCorrection=... events=...

These lifecycle logs capture the data needed to compare recovery anchors. When NINJAM applies either a remote-tempo replacement or its join-alignment correction, the audio callback publishes a receipt only after it has moved the Timer and all local takes. The job thread then emits ninjam-remote-tempo-applied or ninjam-join-aligned. Console output remains outside the real-time callback.

MIDI Is A Separate Cursor

LoopTake::ReadMidiBlock passes its fade-free MIDI cursor to MidiLoop::ReadBlock, which emits events at midiCursor mod loopLength. This is the event timing that must be restored. MidiLoop::LoopPhaseAnchor is different: it is frozen at record end and is used to calculate VST automation fractions. Transport corrections shift the MIDI cursor and apply the inverse value to MidiAnchorCorrection, preserving the automation relationship.

Therefore an exact MIDI restore needs both the event-playback masterAnchor and the automation anchor/correction state. Treating LoopPhaseAnchor as the event cursor would be wrong.

NINJAM Re-Anchor Path

Remote timing commands fan out through Station::ApplyTimingCommand to LoopTake::ApplyTimingCommand, which invokes Loop::ShiftPlayIndex for every playable local loop. The timer command and take commands are consumed at the same audio boundary. For phase discipline and join alignment, one signed delta is applied once to the master and every participating audio and MIDI event cursor; MIDI automation receives the inverse correction in its anchor calculation. This preserves the local relative arrangement.

A remote-tempo replacement is different: it starts a new Timer epoch with the accepted remote interval length and phase, then rebases every local cursor by one common delta. Do not expect a pre-replacement masterAnchor to equal its post-replacement value; take the post-apply snapshot as the new recovery baseline. With an empty session accepting the tempo just requested, the interval should be effectively identical, and the subsequent ninjam-join-aligned snapshot is the direct check that the local scene stayed coherent.

Can a mixed project restore exactly? Yes for its timeline and scheduled MIDI events, provided a save records one coherent block-boundary snapshot: master length, master cycle, master offset, quantisation/grain, global/station/take transport offsets, every audio loop's body phase or master anchor, and every MIDI loop's playback master anchor. MIDI must also serialize its events, length, channel/device routing, quantisation settings, automation lanes and points, LoopPhaseAnchor, and correction state. Store active MIDI note state too if resume must preserve notes already sounding. Exact rendered sound still depends on external VST state and device latency.

Current persistence caveat. The jam format serializes audio loops only. A MIDI-only take is omitted by IoSessionExporter; MIDI events, MIDI playback cursor, automation, and MIDI anchor state are not serialized. Separately, the audio exporter writes MasterLoopCount = 0; the loader calls Loop::Play(masterloopcount, length, false) and does not use saved Index. Current project load therefore cannot restore mixed audio/MIDI alignment exactly.
