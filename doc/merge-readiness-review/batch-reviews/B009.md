## Resolution of B009-R1

The initial review correctly rejected B009 because repeated P3/P4 execution and a static single-call audit were not the callback benchmark required by the approved batch. The correction supplies measured evidence without changing production or inventing a product maximum.

`NinjamTimingProductionBoundary.CommonMapCallbackCostIsBoundedAtSaturationCeiling` builds 32 local Stations with 32 LoopTakes each. Every take has two playable audio Loops and one live MIDI timing cursor: 1,024 takes, 2,048 audio loops, 1,024 MIDI cursors, and 3,072 timing entities. The timed current path invokes the same private `AudioHost::RestoreMappedSourceAtScene` boundary used by the callback. The comparison path reconstructs the pre-B009 Station/take traversal and repeats the same `SyncPhaseMap::SourceCoordinateAt` calculation once for each take before invoking the current neutral per-entity restore. Both paths therefore perform equivalent snapshot, weak-reference, audio-loop, MIDI-cursor, anchor, and own-length-modulo work; their intended difference is common-map calculation placement.

The harness warms each path for 64 calls, alternates measurement order across 11 trials, and executes 64 iterations per trial. Deterministic assertions require 64 current calculations for both the one-take and saturation warm-ups, 704 calculations for 704 measured current calls, and 65,536 warm-up plus 720,896 measured calculations in the 1,024-take reference. Static review corroborates the counter boundary: production contains exactly one `SourceCoordinateAt(` call in `AudioHost::RestoreMappedSourceAtScene`, none in Station/LoopTake, and no lower `MapRemoteElapsedToLocal` call. Final probe audio/MIDI positions and a mapped-coordinate checksum prevent the measured work from being dead or behaviorally empty.

Timing is reported rather than used as a flaky unit-test assertion. The documented acceptance criterion is current p90 below the 10,666,666 ns duration of a 512-sample block at 48 kHz, and current median no greater than reference median × 1.25 + 50,000 ns. Across six independent measurements during this review—the standalone run, three explicit stability repetitions, the focused run, and the full suite—every result reported `timing_accepted=true`. Current medians ranged from 754,328 to 1,080,668 ns and current p90 values from 832,760 to 1,238,010 ns, all comfortably below the block budget. The deterministic counts remained 704 current versus 720,896 reference in every run.

The product defines no configured station/take/loop cardinality limit. Describing 3,072 entities as an explicit saturation ceiling is therefore truthful and is the strongest reproducible in-boundary benchmark available. Introducing a new production cap merely to create a literal maximum would be unrelated behavior outside B009. Live profiling and the absence of a production cardinality cap remain explicit Stage 21/residual evidence; neither is misrepresented as completed here.

## Production and behavior assessment

No production defect was found.

- AudioHost is the only live `SyncPhaseMap` owner. `RestoreMappedSourceAtScene` computes one common source coordinate and fans it through neutral Station/LoopTake methods. Station and LoopTake contain no `SourceCoordinateAt`, `MapRemoteElapsedToLocal`, or copied common-map geometry.
- Engine timing APIs are policy-neutral: `ApplyAcceptedTimingCorrection`, `ResetTimingEpoch`, `CaptureMappedSourceAnchors`, and `RestoreMappedSourceCoordinate` receive only correction/generation or mapped-coordinate values. Station and LoopTake have no NINJAM follow-policy include or parameter.
- Each audio loop retains its own `SceneAnchor`, body position, and length; MIDI retains an independent cursor, length, scene anchor, and automation correction. Restoration applies the common source coordinate modulo each entity's own length. No shared cursor or master-length modulo was introduced.
- An active map is restored before Timer replacement/discipline and map rebase. Rebase changes only AudioHost map geometry/origin and does not recapture existing entity anchors. Initial-map anchor capture remains deferred until after local transport-offset application. Missing late audio/MIDI anchors are captured against the supplied current source coordinate.
- Epoch and `NoSync` reset the AudioHost map, entity scene anchors, and accepted-generation gate without moving cursors or erasing the independent queued local correction. P3 proves disconnected free-run, epoch-2 generation 1 acceptance, and stale/equal rejection with real `M`/`2M`/`3M` audio/MIDI/automation state.
- `SourcePhaseAtOrigin` alone was deleted. `SourceCoordinateAtOrigin`, `SourceCoordinateAt`, derived `SourcePhaseAt`, scene origin, and every per-entity anchor remain live.
- The callback-owned helpers are `noexcept`, use stack values and existing immutable snapshots, and add no explicit allocation, mutex/lock, wait, I/O, formatting, logging, exception flow, or unbounded retry. Their traversal remains proportional to the published station/take/loop hierarchy.
