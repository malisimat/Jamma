Understanding the grid-origin fix

One beat.
Two clocks.
The right zero.

The audio device counts samples since it started. The musical transport counts samples from an accepted interval boundary. Quantised notes must use the same ruler as their grid.

01 / The distinction

Equal units. Different starting points.

Both counters measure samples. That does not make their numbers interchangeable. The device can be running for seconds before a NINJAM join gives Jamma a musical clock.

DEVICE SAMPLE COUNTER · D
662,528 + M

“How much audio has run?”

A timestamp for observing remote phase and projecting it to an audio block. Starting the device earlier changes this number.

MUSICAL TRANSPORT · M
0 → 313,600

“Where are we in the music?”

Timer’s accepted interval begins at musical zero. Capture starts and recorded event offsets are expressed on this ruler. Later intervals add to the absolute musical position.

D = O + M  ·  O is the device timestamp corresponding to musical zero.

Here we model a stable, accepted remote transport with a 1:1 source map. Real observations also carry phase, sample rate, epoch and generation.

03 / What the code actually changed

The grid’s origin. Not the transport.

This particular change is in NinjamTimingCoordinator::_PublishRemoteDesired. It changes the origin metadata sent to MIDI quantisation when a remote grid is published.

BEFORE · a device coordinate fed to musical arithmetic
origin = remotePhaseDeviceSample
       - remoteIntervalPhase;

// Event position is MUSICAL:
event = captureTransportStart
      + recordedEventOffset;

snap(event - origin);

The origin calculation is meaningful in device samples. Subtracting it from a musical event mixes two rulers.

AFTER · both operands use the musical ruler
origin = 0;

// Event position is still MUSICAL:
event = captureTransportStart
      + recordedEventOffset;

snap(event - origin);

Accepted Timer geometry defines musical interval boundaries at zero and its interval multiples. The event and its grid now share that origin.

The invariant: event position − grid origin must subtract coordinates from the same domain. A correct device-space implementation would convert the event to device space first, then convert the snapped result back. Musical zero avoids that unnecessary round trip.
01 / OBSERVE

Keep the timestamp.

The device sample anchor still says when a remote phase was observed. Jamma uses it to project remote timing to the current callback boundary.

02 / APPLY

Establish musical time.

Timer’s accepted replacement sets the remote interval length and phase, and starts its interval count at zero. A nonzero current phase is valid; “zero origin” does not mean “rewind to phase zero”.

03 / SNAP

Use musical boundaries.

Capture start plus event offset gives musical position. Snap it to rounded remote boundaries, convert back to the take, and then compose intentional user offsets.

04 / Why this is a safe correction

A narrower change, with an explicit contract.

✓
Remote authority is retained.

BPM, BPI, interval, phase, observation timestamp and command identity are preserved. This origin change supplies no new tempo or phase authority.

✓
Recorded material is retained.

Quantisation derives a playback event snapshot. The origin change does not rewrite raw recorded notes or resize loop buffers.

✓
Device startup becomes irrelevant.

Changing O while holding musical timing fixed leaves the corrected snapped event unchanged. Try it above.

✓
Intentional offsets still exist.

User, station and global offsets are composed after snapping. Zero grid origin does not erase those controls.

✓
No new callback synchronisation.

The coordinator computes this metadata off the audio callback. The origin correction adds no callback locks, queues, allocations or logging.

✓
The production path is tested.

The regression joins with an empty session, creates a take afterwards, records MIDI, and compares scheduled note output with the click boundary.

What this does—and what remains separate

It removes an unrelated device-epoch shift from MIDI grid arithmetic. It is valid because capture positions already use the accepted musical transport ruler.

It does not prove arbitrary pre-existing loops on a different source ruler align after a tempo change. Those need the source-map conversion and lifecycle to be checked independently. Fractional beat spacing also requires integer sample rounding; short repeated loop lengths can introduce separate rounding questions.

Even sample-aligned MIDI scheduling cannot guarantee a Kontakt sample’s audible attack lands exactly on the click. Plugin processing latency, intentional offsets and the sample’s attack are separate from this coordinate fix.

05 / The useful questions

Keep the boundaries clear.

Did this fix cause the successful “kept time” rerun?

No. The earlier stall fix rejected inconsistent startup geometry: a 1000-sample interval paired with tempo metadata that implied a much longer interval. That prevented a poisoned source map. The grid-origin correction was made afterwards, while investigating the constant audible offset.

Was the device-origin calculation itself wrong?

No. D minus remote phase is a reasonable device timestamp for an interval boundary. The mistake was treating that device timestamp as an origin for an event already expressed in musical transport samples. Correct numbers can still be used in the wrong coordinate domain.

Why did matching BPM not guarantee alignment?

Tempo determines spacing. Origin determines placement. Two grids can repeat at exactly the same rate while every note lands a fixed distance away from a remote beat. At some device offsets the old formula accidentally aligns, which can hide the bug.

What else changed in the alignment fix?

Stations now retain the accepted grid for takes created after joining. The metronome also stopped advancing independently by output hardware latency: clicks and local loop audio already share that latency in the same DAC buffer. Clicks now use the same rounded rational beat boundaries as MIDI quantisation. These are distinct fixes; the interactive origin lab isolates only the coordinate issue.
