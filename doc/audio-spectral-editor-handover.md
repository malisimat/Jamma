## What changed this session

### Resource and lifecycle accounting

The user approved a **512 MiB session-wide admission budget**, preserving committed edits and rejecting new admissions/strokes with visible reasons when limits cannot be met. AudioSpectralResourceBudget is explicitly owned by the shared controller. Immutable source/capture values carry a shared reservation, so worker jobs, playback and history keep admission charged until their last source pin is released off audio.

The conservative estimate reserves six full PCM/gain revisions, three analyses, 64 bytes per envelope sample, WOLA scratch, 64 MiB display allowance and 64 MiB history allowance, plus 36 bytes per coefficient for input maps and reserved dirty indices (two active maps and at most one cancelled in-flight map). Cancellation removes queued input work and immediately drops UI scratch even if a running closure still pins Stroke; normal finish drops both scratch maps before another stroke can start. It reserves the complete worst-case workspace even after an edited Loop closes. This is deliberately conservative: short edited Loops have approximately a 128 MiB minimum charge, and opening several can exhaust the session budget despite lower measured resident memory. It does not silently discard edits. A future measured split between retained and active working memory can improve admission without weakening lifetime bounds.

Stroke submission rejects a stroke whose conservative before/after history cost exceeds 64 MiB. History trims the oldest spectral entries to enforce the global 64 MiB history limit, preserving other application history and current committed edits. Obsolete source/deleted Loop history entries are pruned on the UI tick. Untouched source/analysis data releases on close as before. A first stroke that published a live draft and was then cancelled back to unity can retain the restored Loop-owned source/playback and its conservative reservation after close, until source invalidation/delete. This retention is accounted for but can exhaust admission sooner; reclaiming reverted unity without disrupting transitions/history remains a resource optimization to design separately.

### Gesture/controller/worker orchestration

Ordinary pointer events now rasterize elapsed exposure immediately into a preallocated frame-by-bin matrix. Rasterization visits only hop-lattice rows and frequency bins under the swept oval (with wrapped context), using the same analytic integration as before. It neither copies gain tiles nor performs FFT work, and it cannot allocate after matrix creation. A reserved dirty-cell index list replaces the 128-moving-segment queue, so arbitrary moving samples accumulate while reconstruction is busy. Two maps alternate: UI writes the active map; a frozen handed-off map is read by worker application and UI pending-level feedback. At up to 30 Hz, when a paint receipt is available, all dirty cells are applied in one COW gain transaction. The UI clears/recycles a frozen map only after the terminal release/acquire receipt. Normal release/close drains all captured cells into one Undo entry. Alt bar painting remains on its existing bounded 128-segment lane. Worker edit/content/display scheduling and useful intermediate playback publication remain fair and coalesced per Loop owner.

Ordinary left/right painting integrates swept elapsed-time exposure, including stationary holds. The user confirmed visible raising/falling and successful Alt painting in live testing, then requested a substantially stronger ordinary effect in both directions. Brush centre tuning is now 60 dB/second (2 dB per nominal 30 Hz publication) after the 2026-10-13 request for smooth visible height changes, with the same 50 ms / quarter-octave radii. Display preparation now interpolates normalized dB heights after per-corner gain/envelope scaling; the earlier amplitude-first interpolation made rising corners dominate abruptly. Zero coefficients and saturation produce no edit/history when content is unchanged. Time support wraps, frequency clamps to the explicit lower edge/Nyquist.

### Accurate displayed picking and pointer ownership

LoopGridEditor picks the exact successfully displayed spectral triangles using its exact folded clip-from-local matrix retained from the successful draw and clip-span rays. It requires a fully stable morph, available GPU surface and matching source identity/generation. Flat silence remains hittable; background misses use the existing MIDI orbit functions. HUD priority and latched button/modifier ownership are preserved; right painting cannot trigger ordinary mute.

Bar time mapping freezes camera/model/radius, initial screen Y and hit-height plane. Bar endpoints quantize to the nearest source sample so a fractional screen hit can author exact zero/unity. Horizontal mapping uses that initial Y independently of off-surface vertical level control. Edge-on projection rejects with feedback. Viewport or actual camera/source changes cancel safely; harmless parent layout animation does not. Stationary ordinary painting retains its source coordinate as heights deform, while moved pointers repick the latest displayed surface. DPI comes from the actual Window HWND through Scene's narrow host callback (GetDpiForWindow / 96), not a guessed global scale. Oval/bar outlines, mode/level/silence labels, pending work, memory/overload and peak-above-full-scale feedback are wired.

### Receipts, envelope ordering and waveform

Playback work synthesizes spectral PCM independently and reads the newest committed envelope after synthesis. Final publication checks that envelope handle/revision under Loop's existing off-audio publication mutex; a racing newer envelope rejects composition and causes a bounded retry/latest queued job. No late spectral result can reinstate an older accepted envelope. Envelope-only updates reuse an already accepted PCM handle; unity spectral updates use original PCM directly, with no FFT.

Undo/cancel advances Loop's generation-tagged minimum spectral revision before replacement. Publication and callback pending adoption reject older receipts. Tagging prevents a stale Undo barrier from poisoning a new source generation. Current/previous playback leases, scalar adoption and off-audio reclamation remain intact. Source/gain/PCM owning destruction stays off callback.

Playback creation prepares a fixed 2048-segment min/max overview from composed immutable samples. LoopModel refreshes using snapshot identity even when geometry/length is unchanged, and edited overview updates never read mutable recording banks. Loop UI CommitChanges acquires the immutable playback and refreshes the bounded overview after close and closed-Loop Undo; it never falls back to mutable banks if the source changes between acquisition and refresh. The existing LoopModel cache skips unchanged snapshots. The controller also refreshes newly observed snapshots while open.
