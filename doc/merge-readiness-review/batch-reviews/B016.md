## Independent statement audit

### Interval, observation, and desired-state ownership

- The interval equations are dimensionally and operationally correct:
  `60 * BPI / BPM` seconds and the rounded sample-rate product. They match
  `IntervalSampsFromTempo` in `JammaLib/src/ninjam/NinjamTiming.cpp` and its
  `NinjamTiming.ComputesIntervalLengthFromTempo` coverage.
- `NinjamConnection::_UpdateSnapshot` reads the NJClient timing tuple only
  around a stable even `AudioProc` sequence and associates it with the last
  completed device-audio sample. `AudioHost` projects that remote tuple to its
  callback boundary, adds the callback-time local Timer observation, and
  publishes the combined observation. The callback performs no NJClient timing
  getter call.
- `NinjamNetworkService` mutex-serializes all access to
  `NinjamTimingCoordinator`. The Coordinator owns validation, physical/session
  lifecycle, request and prompt state, full remote BPI, policy selection,
  command generation, and construction of complete
  `NinjamDesiredTransportState` values. `Scene::_ApplyNinjamTimingUpdate` only
  forwards the desired value and remote-grid publication.
- `AudioHost::ApplyDesiredTimingAtAudioBoundary` reads and applies the latest
  newer complete desired value before normal Timer and Station advancement. It
  rejects an older epoch, a non-newer version in the same epoch, and a
  non-newer active command generation in the same epoch. Geometry replacement,
  phase correction, Timer mutation, common-map calculation, and per-entity fan
  out are audio-boundary owned.
- The desired mailbox and AudioHost's private local-offset mailbox are correctly
  documented as separate latest-value contracts. Remote desired state is
  epoch/version/generation ordered and may carry `NoSync`; the local offset is
  an absolute signed local target, includes explicit zero, remains effective
  while disconnected, and is not ordered by remote authority.

The guide's phrase that the callback is the desired mailbox's sole reader is
accurate in the ownership sense: it is the sole consuming reader. The job-side
`AudioHost::PublishDesiredTiming` method also performs a non-consuming
`ReadLatest` monotonicity guard before publishing; it does not apply state or
create another authority/consumer.

### Map, anchors, lifecycle, and generations

- `SyncPhaseMap` contains only local/remote lengths, scene origin, and monotonic
  source coordinate at that origin. It stores no entity phase or entity cursor.
- AudioHost requests entity-anchor capture only when establishing a map that was
  previously absent. Later discipline/rebase operations retain those anchors
  and update only the common origin. A playable entity missing an anchor may
  capture lazily during restore, exactly as the document states.
- Epoch change and explicit `NoSync` reset remote authority, map, Timer and
  LoopTake consume-once generation gates, and entity anchors. They do not apply
  a local audio/MIDI cursor correction. `ResolveTempoChange(false)` publishes an
  explicit `NoSync` with reason `StayLocal`; it does not silently publish
  nothing.
- Session epoch, desired version, command generation, map state, and local
  entity generations are not conflated. The map has no independent authority
  generation. Timer and LoopTake retain audio-side command-generation gates,
  while queued local corrections and reclock/tap state remain local concerns.
- Full BPI is mandatory for valid remote timing and proposal construction.
  Missing BPI cannot create or mutate remote authority. Disconnected BPI
  inference remains a separate pure local Quantiser calculation.
- Replacing accepted remote geometry changes Timer master geometry but does not
  resize local loops. The common mapped source amount is restored/applied
  independently through each entity's own anchor and modulo, preserving
  `M`/`2M`/`3M` and non-divisor positions.

These statements agree with `NinjamLoopAlignment.h`, `AudioHost.cpp`,
`Station.cpp`, `LoopTake.cpp`, and the named Coordinator, production-boundary,
and LoopTake timing tests, including latest substitution, restore-before-rebase,
late independent origins, reconnect, and `NoSync` cursor preservation.

### MIDI, diagnostics, and export

- Device-audio sample, local-master absolute sample, scene coordinate,
  local-source coordinate, per-entity cursor, remote-grid origin, MIDI event
  cursor, and automation global-sample origin remain distinct in current types
  and call sites.
- The accepted remote descriptor contains interval length, authoritative BPI,
  phase/BPM/generation, and the device origin
  `RemotePhaseDeviceSample - RemoteMasterPhaseSamps`. Scene forwards it through
  Quantiser to each LoopTake.
- `MidiQuantisation::BuildQuantisedPlaybackEvents` directly evaluates remote
  fractional boundaries, maps them through each take's transport start and own
  loop length, shifts matched note-offs, and leaves recorded source events
  untouched. `MidiLoop::SetQuantisation` builds and publishes the immutable
  playback snapshot away from the callback. The event cursor and frozen
  `AutomationGlobalSampleOrigin()` remain separate; cursor translations are
  balanced through `_midiAnchorCorrection`.
- The documents do not overstate graphics completion.
  `QuantisationLoopTakeVisual` still carries grain/division-style fields and
  `Quantiser::ActiveGrid()` exposes no accepted remote descriptor. Remote event
  snapping is implemented, while unequal/non-dividing remote-grid overlay and
  the complete live MIDI/overlay scenario remain incomplete or unverified.
- `NinjamTimingCoordinator` owns the diagnostics. Its event ledger has fixed
  capacity 32; disabled capture returns before reason/event work; repeated
  anomalies and post-capacity overflow presentation use first/power-of-two
  summaries; desired lag/caught-up transitions are deduplicated. NetworkService
  adds only mutex-serialized forwarding, and Scene formats/presents diagnostics
  on the job path under Event `verbose`.
- `NinjamConnection::ExportLatencyCompensationEnabled` remains `false`.
  The common integer remote-to-local mapping is phase-preserving rather than
  time stretching and can repeat or skip source audio/MIDI samples.
