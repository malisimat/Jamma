# Audio spectral surface contract

Status: implemented and covered by native spectral/controller/publication tests. Live GPU/input/listening verification remains pending; persistence is deferred. See [current validation and handover](audio-spectral-editor-handover.md). Older validation-history paragraphs below describe the preceding session.

AudioSpectralModel builds a single indexed grid per opening/configuration (prototype default 4095 time by 256 frequency segments, capped by AudioSpectralConfig). An R32F texture holds compressed magnitudes at grid vertices. Updates replace only a changed bounding rectangle; vertex/index buffers do not change with edits. Texture capacity, vertex texture support, shader/palette availability and GL upload/draw failures report useful unavailable reasons and retain the waveform fallback. GL resources use GlDeleteQueue.

Display jobs resample requested magnitudes from the retained original analysis, independent spectral gain field and broadband envelope. This is the specified framewise modulation preview, rather than a new STFT of composed output. Compression uses a fixed reference/floor/ceiling. Each corner magnitude includes spectral and envelope gain before compression; bilinear interpolation then operates on normalized dB heights, avoiding exponential dominance by rising loud corners. An immutable normalized logarithmic viewport determines the displayed minimum/maximum Hz and whether the lower edge includes DC. Positive rows sample this range; a zoomed lower boundary samples its actual frequency. Physical source Nyquist remains separate from the displayed maximum. Time endpoints duplicate the wrapped first column. The explicit colour ramp runs black at exact silence, then dark blue, green, yellow, orange and red. Colours use full emissive brightness above a short lowest-level dark-blue fade, instead of being multiplied by height. Colour spans -90 to 0 dB separately from the unchanged -90 to +24 dB height range. Exact zero has zero height and black colour; there are no pitch/time guides or ambient/hover lifts. A cyan core/trail follows the Loop body phase.

The local rectangle has X endpoints ±R, depth endpoints ±0.78R (low frequency toward +Z), and height 3 to 3+0.25R. It reuses MIDI framing and the existing camera/orbit lifecycle. Mesh vertices morph from an annulus R±5%; the phase rotation matches the old waveform and disappears at the rectangle. The old waveform crossfades with restored GL depth-mask state, and the spectral view bypasses waveform-only mixer/Y scaling. Source preparation completes before the spectral reveal begins. The model and last display survive the reverse close animation and detach at target reset.

Display/picking coherence is explicit: texelFetch supplies exact vertex heights; each cell uses triangles (00,10,01) and (10,11,01). DisplayedSurface retains the successfully drawn immutable heightfield, radius, morph, play fraction and the exact folded clip-from-local matrix from the successful draw. Picking uses this value rather than pending data or the old flat picker mesh, and painting must remain disabled during morph/source acquisition.

Presentation CPU work stays on the dedicated spectral worker; UI/render owns GL upload. The worker has bounded latest pending presentation with explicit cancellation callbacks, and alternates presentation/reconstruction when both are ready. New requests do not repeatedly cancel useful running synthesis. Normal close/source invalidation cancels without joining. Persistent CPU and GL failure feedback is retained per request rather than presenting a permanent preparing message.

AudioSpectralPicking is implemented in isolation: local-ray slab clipping and bounded grid traversal intersect the exact displayed triangles, including flat silence, vertical/grazing rays and grid boundaries. LoopGridProjection now supplies shared local rays for existing planar MIDI projection and raised audio picking. Native numerical validation covers raised/flat intersections and retained transforms under translated, scaled and moved views. Live input/listening verification remains pending. A held ordinary brush retains its source anchor until the pointer moves, while movement repicks the displayed triangles. Parent layout animation does not cancel strokes; actual camera, viewport, source and readiness changes still do. Brush uniforms are explicitly registered and shader outlines use pixel derivatives.

The fixed grid count is independent of source duration and sample rate. CPU LocalVertex/picking and the vertex shader share HeightRadiusScale (0.25). Fragment derivatives of the interpolated local surface position provide a restrained fixed-light specular cue before brush/playhead overlays; silence stays black. Live GPU appearance still requires visual acceptance.

Display preparation caches logarithmic row-bin mappings and unclamped per-corner dB for identical frame pairs, reusing the previous next-frame pair when it becomes the first pair. Changing envelope gain adds one per-column dB offset; every corner is compressed and clamped before interpolation. Scratch is bounded to frequencySegments+1 worker-local records, freed on completion/cancellation, and stays within the existing display allowance. Coincident dense/sparse vertices retain identical height-domain interpolation.

Wheel controls resize physical brush support: plain wheel adjusts time/octave radii together; Alt+wheel adjusts the broadband time band, with Alt taking precedence over Shift/Ctrl. Shift+wheel zooms the logarithmic frequency range, Ctrl+wheel pans it, and Ctrl+right dragging on the surface pans vertically/zooms horizontally while holding the first frequency under the projected pointer, like the MIDI pitch view. Ordinary right attenuation and off-surface orbit retain their bindings. Captured gestures reject wheel/navigation; after edit release, input stays blocked until its final worker receipt. Radius controls are bounded to 5 ms to 2 s and 1/16 to 4 octaves; frequency view spans at least 1/16 of the full log range.

Viewport controls are UI-owned. Display jobs receive immutable viewport/serial captures, and completed metadata travels with the heightfield through the existing model publication mutex. Display sampling, CPU hit-to-Hz mapping and shader-normalized brush footprints all use that displayed metadata. Independent presentation revisions allow a same-edit viewport rebuild and reject obsolete receipts. The controller accepts only its requested viewport and suppresses obsolete failure feedback. A new edit cannot start until requested and successfully displayed viewports agree. Captured editing cancels on a changed displayed viewport/camera/radius; navigation permits intentional viewport changes but cancels on camera/radius/size/source loss. Close cancels all display jobs off audio.

The lowest palette fade spans only 0.03 normalized colour height (2.7 dB); true zero remains black. The UI outline uses lattice-aware physical brush support. The 4096 by 257 height texture fits a 4096 maximum texture width. Host geometry is about 32 MiB; up to five distinct 4.016 MiB heightfields plus row caches fit the unchanged 64 MiB host allowance. GPU resources are separate: about 32 MiB vertex/index storage plus 4.016 MiB texture. Display compression caches uncompressed per-corner dB independently of changing envelopes, adds one per-column envelope dB, clamps every corner before height interpolation, and reuses a previous next-frame pair when it becomes the first pair.
