NINJAM local-loop transport continuity

Outcome: a NINJAM timing replacement no longer makes the VST transport jump backwards. Local loop playback is instead aligned by a bounded, forward-equivalent circular correction, then driven from a monotonic scene timeline. The original local master ruler remains the reference while following the remote session.

What changed

Remote observation / replacement │ ▼ Timer accepts remote tempo and remote musical phase │ (scene sample position never rewinds) ▼ Map remote phase/delta → original local source-master ruler │ ▼ Apply one bounded circular translation to every local LoopTake │ ▼ Each LoopTake restores its own audio and MIDI cursors from its own anchor using its own loop length and intentional offset.

Why this preserves different LoopTakes

A station-wide command is a translation in common source time; it is not a demand that every loop be at phase zero. Each LoopTake stores an anchor at the same scene coordinate, but calculates its position modulo its own audio/MIDI length. Consequently a 1-bar MIDI take, a 3-bar audio take, and deliberately offset takes retain their relative arrangement. Only the designated local master reaches zero at the next remote interval wrap.

The remote-to-local conversion is integer based and shared by both correction and subsequent restoration. Thus a whole remote interval always maps to exactly one whole local master interval; there is no competing rounding rule for audio versus MIDI.

Old versus new

ConcernPrevious behaviourNew behaviour
VST host sample timeReplacement reset the musical timer and could drive the host time near zero.Scene time is 64-bit and monotonic. VST2/VST3 receive that timeline; remote musical phase is separate.
Unequal rulersRemote samples could be treated as local samples.Remote elapsed time and phase are mapped onto the original local source ruler before correcting takes.
Relative loop timingLarge timer rewind exposed different block residues, causing audio and MIDI loops to lose their intended relationship.Every take is anchored at one scene boundary and restored from its own anchor and loop length.
Timing correctionsA correction could become an externally visible multi-minute transport discontinuity.A circular source-ruler difference gives the equivalent bounded local correction; no backwards VST transport jump is sent.
UI scene offsetCould be confused with remote musical phase.It remains loop-local. When it changes with a new map, anchors are captured after the offset has been applied.

Design boundaries

  • The Timer’s phase is the remote phase exactly. The UI offset never changes that protocol fact.
  • The follow-session source-master length is retained across later remote tempo replacements, so an unequal replacement cannot silently redefine the local ruler.
  • VST3 playing and validity flags are set explicitly; VST2 does not advertise a PPQ value that is no longer derived from the monotonic host timeline.
  • The audio callback uses the existing immutable station snapshot and mailbox command hand-off; it introduces no callback lock or allocation.

Verification

The native suite was rebuilt and run after review: 808 tests passed and one environment-dependent MIDI-device test was skipped. Coverage checks exact next-wrap mapping for unequal local/remote rulers and that the scene timeline remains monotonic over a timing replacement. A further regression now covers the important mid-interval rounding case: the next rebase derives the actual source phase from the active map origin, not from a fresh rounded phase lookup. The focused plan and implementation checklist is in doc/ninjam-vst-transport-continuity-plan.md.

Independent review result

The separate reviewer confirmed that per-LoopTake fan-out is the correct ownership model: the same source-time correction is applied to every local take, then each takes its own modulus. It identified a one-sample unequal-ruler rebase error, caused by recomputing the old phase statelessly after rounding. This has been corrected with a NINJAM SyncPhaseMap value object, owned by AudioHost, that retains { scene origin, source-phase origin, local length, remote length }. That small value object also removes the previous double anchor-capture pass; map anchors are now captured once, after any loop-local UI offset is applied.

The reviewer also noted a bounded follow-up: VST2 no longer advertises an invented PPQ value, which is safer, but sync-sensitive plug-ins may eventually benefit from an explicit non-wrapping musical-epoch map. This is intentionally separate from the safety fix; monotonic sample time is retained now rather than fabricating a beat position.
