## Finding

### B008-R1 — job remote-snapshot visits bypass the published take snapshot

`Scene::OnJobTick` correctly computes `hasLocalContent` from `Station::GetLoopTakeSnapshot()` at `JammaLib/src/engine/Scene.cpp:1329`-`:1338`, but uses that value only on the no-snapshot `TickTiming` branch. When `Pump()` supplies a remote snapshot, `OnJobTick` calls `_HandleRemoteTempoSnapshot` at `:1346`-`:1347`; that helper independently recomputes `hasLocalContent` with `station->NumTakes()` at `:324`-`:329` before calling `ObserveTiming`.

`Station::NumTakes()` selects and reads `_backLoopTakes.size()` or `_loopTakes.size()` (`JammaLib/src/engine/Station.cpp:1410`-`:1415`). Callback-reachable `Trigger::OnTick` flushes delayed trigger actions (`JammaLib/src/engine/Trigger.cpp:300`-`:319`, `:552`-`:570`), and the resulting Station ditch erases from `_backLoopTakes` and publishes a new take snapshot (`JammaLib/src/engine/Station.cpp:1259`-`:1276`). Therefore, a normal job visit carrying a remote snapshot still bypasses the published snapshot and can race the callback-owned take mutation. It can also send an incoherent local-content answer into the coordinator precisely on the live observation branch.

The correction is within B008's existing boundary: use one snapshot-derived local-content value consistently for both `ObserveTiming` and `TickTiming` (or make `_HandleRemoteTempoSnapshot` itself use the published take snapshot), then add or tighten focused coverage so the remote-snapshot branch is exercised during final-take removal. Do not broaden the fix into B009 map work, B014 diagnostics, or the separate deferred-trigger implementation.
