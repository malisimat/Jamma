## Blocking findings

### B005-R1 — The production path cannot reach the no-observation deadline while physically connected

`NinjamSession::Pump` assigns `result.Snapshot = conn->Snapshot()` whenever its physical timing status is available (`JammaLib/src/ninjam/NinjamSession.cpp:483`-`:487`), and `NinjamConnection::Snapshot` always returns the cached value object (`JammaLib/src/ninjam/NinjamConnection.cpp:771`-`:774`). In `Scene::OnJobTick`, any such snapshot takes `_HandleRemoteTempoSnapshot`; `TickTiming` is called only in the mutually exclusive no-snapshot `else` branch (`JammaLib/src/engine/Scene.cpp:1412`-`:1416`). A socket-connected session therefore never advances the new observation-independent Tick path.

The fallback through `Observe` does not provide equivalent stale-observation detection. It sets `_lastValidObservationAt = now` before the timing tracker can classify the value as duplicate (`JammaLib/src/ninjam/NinjamTimingCoordinator.cpp:121`-`:145`). Both the Connection snapshot and AudioHost latest-value path may repeat the last completed B004 observation when no newer audio observation exists, so each job visit refreshes the deadline despite no fresh timing anchor. The only production calls to `TickTiming` and `NinjamTimingCoordinator::Tick` are the unreachable-while-available Scene/NetworkService chain.

Consequently a physically connected session whose B004 observation stops advancing can retain stale timing authority indefinitely instead of emitting exactly one `ObservationDeadline` `NoSync`. P8 passes because it invokes `coordinator.Tick(...)` directly at `test/JammaLib_Tests/src/ninjam/NinjamTimingCoordinator_Tests.cpp:598`-`:605`, bypassing the production routing defect. This does not satisfy F-028's observation-independent production recovery or F-041's production-faithful seam.

Correction must remain inside B005: advance the deadline from the job owner independently of snapshot presence, distinguish a genuinely fresh B004 observation from a repeated cached value without creating a second observation owner, and add a production-boundary regression proving valid timing -> physically available but no fresh observation -> one `NoSync` -> repeated idempotence -> fresh valid recovery. It must not pull in B006 desired-state/gate or B009 map work.

### B005-R2 — P7 does not cover the replacement/persisted lifecycle edges claimed by the batch

P7 calls only the pure `NinjamSession::AdvanceTimingStatus` helper with `false -> true -> false -> true`, then forwards those values directly to the coordinator (`test/JammaLib_Tests/src/ninjam/NinjamSessionTiming_Tests.cpp:6`-`:44`). That helper is used by production Pump, so its scalar transition assertions are truthful, but the test never calls `NinjamSession::Start`/`Pump`, never observes `_forceUnavailableEdge` (`JammaLib/src/ninjam/NinjamSession.cpp:388`, `:467`-`:473`), and never traverses Controller pending-snapshot clearing (`JammaLib/src/ninjam/NinjamController.cpp:32`-`:44`) or Scene remote-station cleanup (`JammaLib/src/engine/Scene.cpp:1405`-`:1411`). It also does not cover the persisted/default `Scene::FromFile -> PrepareTempoSyncOnConnect -> LoadConfig -> Session::Start` chain (`JammaLib/src/engine/Scene.cpp:664`-`:671`) or manual replacement compatibility.

This is material rather than theoretical: the required replacement-session unavailable edge was added later in `4e99584` without any P7 change, and P7 would pass if that correction were reverted. The three JamFile checks rerun below prove JSON default/optional-field parsing only; they do not exercise lifecycle startup. Static inspection supports the intended call chains, but the approved B005 prerequisite requires deterministic evidence for the explicit replacement edge, stale pending snapshot/station cleanup, and fresh epoch. Add a minimal existing-owner production seam/test for those operations; do not add a raw connection/buffer API or require a live server.

## Confirmed behavior and scope audit

- Physical status and epoch are job-owned and runtime-only. `AdvanceTimingStatus` increments the epoch only on an unavailable-to-available edge and skips zero on wrap (`JammaLib/src/ninjam/NinjamSession.cpp:449`-`:461`). `Start` publishes a forced unavailable edge before a replacement can report success (`:365`-`:417`, flag at `:388`).
- Once a physical loss reaches the coordinator, `_EnterNoSync` is edge-triggered and clears tracker, request, prompt/proposal, join, and validity state (`JammaLib/src/ninjam/NinjamTimingCoordinator.cpp:62`-`:85`, `:336`-`:368`). Repeated physical/invalid/deadline calls return no second `NoSync`; valid recovery reconnects the tracker.
- The B004 remote tuple remains job-owned. Connection Pump clears it and the cached snapshot on the connected-to-failure edge before retry (`JammaLib/src/ninjam/NinjamConnection.cpp:354`-`:410`, clear at `:383`-`:390`); `_UpdateSnapshot` remains the publisher (`:960` onward). Controller clears a pending snapshot on the unavailable edge, and Scene sends an empty remote-station snapshot on that same job-owned transition.
- Interactive connect still prepares coordinator state and publishes the existing reset before starting the physical connection; manual disconnect still resets coordinator state, publishes one existing invalidation, stops the Session, and clears the pending snapshot (`JammaLib/src/engine/Scene.cpp:254`-`:310`; `JammaLib/src/ninjam/NinjamController.cpp:64`-`:89`). No B006 gate reset, B009 common map, persistence/schema, or callback ownership change was pulled forward.
- No changed callback/hot-path body gains a lock, allocation, wait, logging, I/O, hierarchy traversal, or container destruction. The changed Connection logic is in job-owned `Pump`; the changed Scene logic is in `FromFile`/`OnJobTick`; AudioHost and the audio callback are untouched.
