## Blocking findings

### 1. Post-capacity output is not transition-only or rate-bounded

Accepted F-034 requires transition-only/rate-bounded off-thread formatting, and the Stage 17 contract requires repeated anomalies to use first-occurrence reporting plus a suppressed-count summary. The implementation bounds retained array storage to 32 events, but does not bound repeated output over time:

- `NinjamTimingDiagnostics::Capture` updates `LatestEvent` and increments `EventSequence` for every enabled event, including every event after the 32-slot array is full (`JammaLib/src/ninjam/NinjamTimingCoordinator.cpp:24`-`:42`). It also increments `EventOverflowCount` for every post-capacity event.
- `Scene::_LogNinjamTimingDiagnostics` prints `LatestEvent` whenever its sequence advances and separately prints the overflow total whenever that counter advances (`JammaLib/src/engine/Scene.cpp:461`-`:473`).
- `Scene::OnJobTick` polls and presents these values on every verbose job tick (`JammaLib/src/engine/Scene.cpp:1317`-`:1321`). There is no per-reason transition gate, first-occurrence state, elapsed-time limiter, or suppression-summary interval for observation, tracker, or safety anomalies.

Consequently, after the retained array fills, one repeated invalid timing observation per job tick advances both values and remains eligible to print one latest-event line plus one overflow line on every tick indefinitely. This is bounded memory and bounded work per poll, but not the approved bounded-rate/suppressed-volume diagnostic behavior. The five diagnostic tests prove array capacity and overflow accounting only; they do not exercise Scene presentation after overflow or repeated-anomaly suppression. The pending manual bounded trace cannot close a statically absent suppression/rate mechanism.

### 2. A Coordinator rejection path has no reason

After a tracker join/wrap event, `NinjamTimingCoordinator::Observe` rejects phase-command publication when `timing.LocalTransport.MasterLengthSamps` is zero or exceeds `unsigned int` (`JammaLib/src/ninjam/NinjamTimingCoordinator.cpp:376`-`:378`). That return has no `_CaptureDiagnostic` call and no dedicated reason/counter. It occurs after the observation has passed presence/proposal validation and after tracker state/counters may have advanced, so it is a distinct dropped-correction validation path rather than an ordinary duplicate/no-event return.

`NinjamTimingDiagnostics.EveryCoordinatorRejectionHasOneBoundedReason` covers disconnected, zero remote interval, generic invalid, sample-rate, tempo, BPI, missing anchors, invalid derived grid step, tracker-backward, and safety-limit paths, but it does not cover this local master-length guard (`test/JammaLib_Tests/src/ninjam/NinjamTimingCoordinator_Tests.cpp:194`-`:281`). B014 therefore cannot claim complete Coordinator rejection reasons.
