## System understanding

There are three useful but disconnected timing signal families. First, the coordinator owns bounded counters and last-emitted-command metadata (`NinjamTimingCoordinator.h:117`–`:143`), populated on the job-owned timing path (`NinjamTimingCoordinator.cpp:106`–`:112`, `:232`–`:265`, `:330`–`:331`, `:347`–`:351`, `:382`–`:387`). Second, `AudioHost` publishes a coherent latest applied receipt containing mailbox sequence, generation, command type, follow policy, scene coordinate, and applied delta (`AudioHost.cpp:113`–`:133`, `:321`–`:329`). Third, `Scene` and `Station` format request/policy/alignment text and inspect the live hierarchy (`Scene.cpp:489`–`:570`; `Station.cpp:2327`–`:2475`). The first two are compact value contracts worth retaining and extending in their existing owners. The third is debugging residue that duplicates orchestration in `Scene`, places a 149-line diagnostic traversal in `Station`, and leaves eleven never-written atomics plus a reader in every `LoopTake`.

No timing-specific assertion is present in the reviewed production seams. That is not independently a defect: disconnect, delayed publication, invalid observations, and safety rejection are recoverable runtime states in release builds, so bounded state/reason telemetry is more useful than a debug-only assertion. Assertions must not be added to the callback as a substitute for the accepted state, epoch, and publication fixes.

The supported contract should be one correlated timing trace owned and formatted off-thread by an existing NINJAM/job owner. It should use the configured timing/event verbosity, not require the unrelated audio hierarchy logger, and should distinguish:

- **Info, transition-only:** physical session availability/epoch; request queued/sent/retried/acknowledged/expired; prompt decision; desired follow policy and reason; remote geometry replacement; `NoSync` invalidation; and the audio-confirmed applied desired state.
- **Warning, transition or first occurrence plus suppressed-count summary:** physical loss/retry exhaustion, timing-validity loss, safety-limit rejection, mailbox/capture overflow, or desired state not observed as applied within a bounded diagnostic interval.
- **Verbose, bounded rate:** timestamped remote observation, desired/applied version and coordinates, phase delta, observation age, phase-error histogram/counters, and at most a fixed number of anomalous entity summaries with an overflow count. Do not dump every entity on every correction.
- **Disabled:** no callback diagnostic call, branch, hierarchy walk, capture, formatting, or I/O. If an explicitly enabled mode needs exact boundary data, only a fixed-capacity/preallocated value record may be captured there; strings, identifier formatting, traversal for logging, and output remain off-thread.

## Candidate findings

### S17-01 — Replace cross-layer hierarchy dumps with one bounded correlated timing diagnostic contract

- Stage / reviewer: Stage 17 — Observability and diagnosability; refines accepted F-019/F-034 and the human-directed `Scene`/`Station`/`LoopTake` slimming.
- Scope reviewed / exclusions: supported audience, identifiers, level/gating, and volume of timing diagnostics. Callback reachability/cost is consumed from Stage 8 and not re-proved; log wording corrections are consumed from Stage 15.
- Severity: must fix before merge.
- Evidence: timing configuration is only four free-form strings (`JammaLib/src/base/LoggingConfig.h:7`–`:13`). Initial tempo-join output bypasses those gates (`JammaLib/src/engine/Scene.cpp:278`–`:284`), while policy/request/applied output uses `Event == "verbose"` (`Scene.cpp:415`–`:430`, `:489`–`:570`) and hierarchy snapshots separately require `Audio == "verbose"` (`Scene.cpp:471`–`:480`; `Station.cpp:2327`–`:2336`). This makes a complete trace depend on two unrelated gates. The hierarchy implementation exposes `Station::LogLocalLoopAlignment` (`Station.h:182`–`:184`), keeps a private formatter (`:298`–`:299`) and mutable before-state vector (`:398`), and emits one station line plus one line per live audio/MIDI entity (`Station.cpp:2363`–`:2475`). Calls also remain at `Station.cpp:807`–`:809`, `:1104`–`:1108`, `:1194`–`:1198`, and `:2299`–`:2302`. The embedded `AlignmentReceipt` branch (`Station.cpp:2378`–`:2394`) is permanently empty because its type/API/eleven atomics/reader (`LoopTake.h:93`–`:106`, `:252`, `:420`–`:430`; `LoopTake.cpp:691`–`:715`) have no writer, as accepted F-019 proved. These diagnostics originated as debugging in `dcfaf1d`, expanded in `6abf7c7`/`b90f398`, and were further formatted in `e0f669c`; compact coordinator telemetry was separately added by `b9619b9`.
- Why it matters: the current surface is simultaneously too large and not reliably useful. It bloats the three human-named engine classes, can produce hierarchy-proportional bursts, yields incomplete before/after traces under split gates, and retains dead fields. Unconditional timing output also violates the decision that retained loop/sync logging is configuration-gated.
- Recommended disposition: consolidate, simplify, and remove. Keep compact coordinator state and the coherent AudioHost applied receipt, and format their correlated records off-thread in an existing NINJAM/job owner. Remove the dead F-019 receipt path and remove `Scene::_LogAppliedNinjamLoopAlignment`, `Station::LogLocalLoopAlignment`, `Station::_LogLocalLoopAlignment`, `_ninjamBeforePositions`, and their timing-only calls/storage once the replacement signal is verified. Use session epoch plus desired/applied state version as primary identifiers; retain request ID, generation, policy, action/reason, geometry, correctly named coordinates, and delta. Default output is transition-only; repeated anomalies use counters/suppression summaries; optional entity detail has fixed capacity and an overflow count. Do not add a logging class or broad logging framework. Preserve the fixed F-034 rules: zero disabled-path callback work; bounded preallocated capture only when explicitly enabled; formatting/I/O entirely off-thread.
- Protected timing concepts affected: diagnostic mirrors only. Remote authority, local Timer geometry, remote master phase, device-audio observation sample, monotonic scene/source coordinates, mapped elapsed time, per-entity audio/MIDI phase, automation origin, and follow policy remain distinct.
- Verification: static audit removing all timing formatter/I/O and diagnostic hierarchy traversal from callback call chains; compile-time or instrumented proof of zero disabled callback work; native test that enables bounded capture, fills capacity, reports overflow, and correlates desired/applied epoch/version; normal and verbose empty/populated join, record, overdub, `Stay local`, disconnect, and reconnect traces; assert a fixed upper bound on records/entities per interval. Remove only the permanently absent receipt line and obsolete hierarchy dumps, not the supported transition signal.
- Human decision: pending Phase 3 gate.

### S17-02 — Timing diagnostics lack rejection reasons and one session-to-audio correlation identity

- Stage / reviewer: Stage 17 — Observability and diagnosability; observability companion to accepted F-024–F-028/F-032, not a duplicate correctness finding.
- Scope reviewed / exclusions: whether existing state exposure explains why remote timing was ignored and whether desired authority can be matched to applied authority. Correct transition semantics, validation, and session epoch implementation remain with their accepted findings.
- Severity: must fix before merge.
- Evidence: the coordinator drops disconnected, invalid, or zero-length timing with no diagnostic update at `JammaLib/src/ninjam/NinjamTimingCoordinator.cpp:76`–`:77`. Tracker rejections for disconnected/zero interval and implausible backward movement increment the same undifferentiated counter (`NinjamTimingTracker.cpp:28`–`:33`, `:56`–`:64`). A safety-limit rejection stores only a count, after updating aggregate maxima/buckets (`NinjamTimingCoordinator.cpp:241`–`:256`). `NinjamTimingDiagnostics` contains totals, maxima, and only last emitted command type/generation (`NinjamTimingCoordinator.h:117`–`:143`); it has no last rejection reason, last rejected coordinates/value, physical session epoch, desired-state version, or matching applied-state version. Production output exposes only request totals (`Scene.cpp:507`–`:514`). The applied receipt is coherent and useful but contains only command sequence/generation/type/policy/scene/delta (`AudioHost.cpp:113`–`:133`), so it cannot distinguish an automatic physical retry from an explicit join or identify the complete desired geometry/observation that it applied. The current Scene join ID increments only for explicit `ConnectNinjam` (`Scene.cpp:257`–`:260`), the exact gap accepted F-027 addresses. Existing diagnostic fields were introduced by `f36bfe7`/`b9619b9`; later debugging commits did not add the missing correlation.
- Why it matters: when timing is stale, rejected, lost during retry, or accepted but not reflected in local playback, support cannot tell whether the failure occurred at validity filtering, tracker classification, policy selection, desired-state publication, audio application, or invalidation. Aggregate counters show that something happened but not which session or state caused the symptom.
- Recommended disposition: extend the existing coordinator/desired-state/applied-receipt value contracts rather than create a parallel logger. Add fixed reason counters plus a bounded latest-anomaly record for validity loss, tracker rejection, safety rejection, and diagnostic overflow. After the accepted complete-desired-state/session-epoch work, expose the same session epoch and desired-state version at observation/decision/publication and audio application, along with physical availability, action/reason, full remote geometry, remote phase, `DeviceAudioSampleAtObservation`, applied scene/device boundary, and applied delta. Log state changes and first anomalies; suppress duplicates into counters and emit bounded summaries. A mismatch signal compares latest desired with latest applied after a bounded interval—it must not resurrect the rejected assumption that every intermediate command is consumed.
- Protected timing concepts affected: session epoch, remote authority, desired/applied state lifecycle, follow policy, remote geometry, remote master phase, device-audio observation coordinate, Timer absolute coordinate, scene coordinate, and per-entity phase remain separate fields and authorities.
- Verification: native table tests for every rejection reason and counter; invalid/disconnected/zero/non-finite/implausible-wrap/safety-limit cases retain the attempted reason without state mutation; two-session reconnect verifies epoch correlation and no session-1 signal is reported as session 2; desired/applied trace tests cover geometry replacement, unchanged-geometry discipline, and `NoSync`; delayed application produces one bounded lag warning/summary and clears it when the matching state is observed; manual cable/server loss and retry trace is readable without hierarchy dumps.
- Human decision: pending Phase 3 gate.

## Uncertainties

- No interactive NINJAM trace was captured. The symptom map is based on static writers/readers, field semantics, test consumers, and history; manual support readability and exact console/TUI behavior remain verification items.
- The final existing owner for off-thread formatting depends on Phase 4's accepted ownership consolidation. `NinjamTimingCoordinator`/`NinjamNetworkService` already own bounded timing state; this report requires reuse of an existing owner but does not preselect a new class or cross-layer dependency.
- Exact fixed event/entity capacity and lag-warning interval need a measured/configured bound during batching. The contract is fixed-capacity with overflow/suppression accounting, never dynamic growth or an unbounded per-entity dump.
- Stable station/take/loop identifiers are currently string-valued. An enabled callback capture must not allocate or format them; Phase 4 must either capture an existing bounded stable token and resolve it off-thread or limit exact-boundary data to numeric timing values and correlate a separately published immutable membership view. This is an implementation constraint, not permission for callback string work.
- Connection errors may appropriately remain visible at a warning/error level even when verbose timing detail is disabled. The repository has no typed severity logger; this report does not authorize a broad logging-framework migration. The Phase 3 gate should decide whether warnings obey the existing event configuration or are always emitted, while all verbose timing detail remains explicitly gated.

## Conclusion

Stage 17 found two bounded timing-observability issues. First, the accepted F-019/F-034 cleanup needs an explicit retained contract: compact coordinator state plus audio-applied receipts should become one off-thread, configuration-gated, correlated, rate-bounded trace, while the dead `AlignmentReceipt` and large Scene/Station hierarchy dump surface are removed. Second, current aggregate counters cannot explain rejection causes or correlate physical session authority through desired state to audio application; the accepted complete-state/session-epoch work must expose reason counters and a bounded latest-anomaly record using one shared epoch/version identity.

The symptom-to-signal map above is complete for the timing-only scope. No separate assertion defect was found, and no additional finding is raised for general logging, retained HUD/VST3/window/tooling/unrelated MIDI/resources, production naming, or broad security. No cleanup was implemented and no protected timing concept was collapsed.
