## Required result

Station, LoopTake and supported Loop rack owners use the same modern channel grid and cable behavior for live and recorded MIDI. Instruments must produce audible output, including a take containing MIDI and no audio recordings. Existing Station sound, routing identity, note editing recovery, timing and mute behavior remain protected.

**Filters are independent, never cumulative.** All incoming MIDI events from the existing rig/device wiring reach every descendant input regardless of ancestor channel masks. Station `{4,5}`, Take `{2,3}`, Loop `{1,6}` must each receive its own channels. The same holds with an empty Station or Take mask. A parent's mask and cables apply only to its own MIDI destinations. Forwarding does not mean passing MIDI through a parent's plugin; plugin MIDI output is outside this change.

Do not restore inactive decorative child grids before delivery, rendering and persistence work. Do not equate plugin insertion with working MIDI input.

## Concrete proposed semantics and decisions for the user

These choices make the implementation bounded and coherent. Confirm the three product choices below before implementation; they do not block committing this proposal. Independent parent/child filtering above is already a requirement and is not open.

1. **Loop means the existing audio leaf for this first implementation.** A Loop rack receives live wired input and recorded MIDI from all streams of its containing Take, filtered by that Loop's own channel grid. It does not receive other takes' recorded streams. A Take rack receives its own streams; Station retains all its takes' streams. These are parallel MIDI recipients, so configuring several instruments intentionally layers them. There is no arbitrary audio-channel/MIDI-channel or vector-index pairing. Each audio leaf retains its own audio geometry; MIDI scheduling retains the MidiLoop's geometry. The grid changes recipients, not either cursor. Pure MIDI takes use the Take rack because they have no audio leaf. Individual MidiLoop racks would require explicit selection, ownership, serialization and render-bus work and are a separately approved extension, not a hidden first-step abstraction.
2. **Rack grids affect destinations, not recording admission.** Recommended recording default: preserve all rig-wired MIDI channels permitted by the recording action/device selection in shared capture history and admit them to a new MIDI recording independently of rack masks. Existing take stream/device selections remain source policy. A filter edit never destroys history or recorded bytes. Station audible behavior stays filtered, but previously discarded channels may now be stored; update the old `RecStartUsesStationAllowedChannels` expectation deliberately. If preserving that storage policy is required, introduce a separately named recording-channel setting with its own persistence and UI in an amended plan; do not silently keep the Station rack mask as a child gate or initialize a permanent hidden gate from it.
3. **Legacy children remain MIDI-disabled when child routing fields are absent.** Existing child instruments previously received no routed notes; loading old sessions must not suddenly layer new sound. Explicit empty means disabled too, while new child owners start with all channels enabled and no cables. Station legacy/default semantics stay unchanged. New child configuration is saved explicitly, including an empty enabled list. Existing audio effects continue processing regardless of MIDI-enabled state. No independent enable toggle is needed beyond the grid.

Live MIDI is broadcast to descendants on wired input, not gated by selection or editor hover. Preserve current capture-pending/cancellation and retained Station mute policy for recorded playback. Child instrument output is part of that child's audible bus and therefore obeys its mixer/mute and inherited Station recorded-mute gate. Parent destination-filter changes must not silence child voices. Preserve live monitoring policy explicitly in tests, including the fact that Station retained recorded mute currently leaves its live rack path independent (`doc/midi-channel-routing.md`, Retained station mute).

## Ownership and prepared delivery

Retain the Station-owned `MidiDelivery` collaborator as the delivery and callback-accounting boundary for one Station hierarchy. Give Take and audio Loop owners local enabled masks, `MidiChannelRoute[16]`, and revision-aware mutation/restore methods beside their current rack lifecycle. Reuse RackState's focused route normalization and validation (`vst/RackState.cpp:295`, `:660`); avoid transplanting Station lifecycle wholesale or adding a generic routing graph.

Extend prepared delivery with immutable rack records (owner identity, exact chain, render width, permissions and destination lists), per-source fanout lists, per-channel live destination tables, and pinned retired destinations. A physical plugin instance has one MidiDestination and one MIDI block lifecycle. Bindings remain keyed by source take, MidiLoop and destination identity, never by presentation/output index. Reorder keeps the instance/state ID and ownership; cables never migrate to a replacement instance by slot index.

Prepare channel eligibility and resolve plugin IDs off callback. Preserve all modern semantics: 1-16 UI/serialization versus 0-15 event channels; disabled clears that owner's cables; re-enable and removal of last cable broadcast; explicit unavailable identities stay silent/cabled; many-to-many routing; route addition enables that owner's channel; rejected/stale/cancelled gestures change nothing. Audio order does not imply plugin-to-plugin MIDI supply (`midi/MidiDelivery.cpp:104`).

Use a single immutable accepted Station render topology containing/pinning the exact child render configurations and chains used for that block. Existing child chain publications cannot be independently reborrowed mid-block for a newer chain than delivery prepared. Child edits notify/rebuild the Station topology on the serialized structural owner. Pass prepared child records down render calls; borrow once at the boundary rather than exhausting snapshot leases through nested borrows. Pin exact MidiLoop source membership with the same accepted topology and pass prepared source records into ReadMidiBlock instead of independently borrowing its latest membership (`LoopTake.cpp:2372`). Source event/edit snapshots may still use their existing per-source lease/recovery contract. A newly added source is not read until its matching prepared fanout is published; a removed source retains its pinned cleanup bindings. Never reconcile source membership through callback string/ID lookup. Immutable topology protects lifetime; MIDI queue/held state stays callback-owned. Any shared mutable processor/config state still needs its existing publication discipline. Check ReadSucceeded separately from an empty publication. On bounded borrow failure, emit no new block output/attacks, do not drain ingress or read recorded sources against mismatched state, and record a callback-owned discontinuity marker for bounded recovery at the next successful block. No retry loop or additional lease acquisition may hide failure. Test repeated failure, queue pressure and resumed held-note cleanup, plus concurrent MIDI membership publication and individual source-snapshot borrow failure without consuming or misrouting an unmatched source.

## Event flow and render order

1. MidiRouter preserves rig/device recipient selection and timestamp mapping, but removes Station rack-mask gates from both live ingress and observation paths. Keep one existing bounded Station ingress queue rather than allocating or copying a queue/vector per descendant. Physical source-loss identity/revisions remain attached to input; rack-filter retirement is a separate owner-local operation.
2. At the Station block boundary, acquire one coherent prepared topology, apply retirement/latency changes, update host time and call BeginMidiBlock once for each active or retiring processor that will be processed. Retired output uses prepared discard scratch. Pass the wrapping device block timestamp to child renders; preserve continuous SceneSamplePos and musical position semantics (`Station.cpp:584-612`).
3. Drain the existing bounded live ingress once. Dispatch each const event directly through prepared channel tables; no intermediate per-level event copies or channel intersection. If a block view is useful to downstream code, it is a fixed-capacity callback scratch view valid only until the block ends. Plugin input queues may necessarily copy accepted events. Never store an ingress reference in a scheduled entry.
4. Invoke each Take's ReadMidiBlock exactly once per rendered device block, independently of whether the Station rack exists. Its synchronous sink receives each event plus voice provenance and source identity, and directly fans out to the prepared eligible Station/Take/Loop destinations before audio rendering. No recorded event buffer needs copying across hierarchy levels. Preserve the existing aggregate acceptance/retry contract across partial destination rejection (`MidiDelivery.cpp:739-788`); a source advances once, accepted destinations do not retrigger when another rejects. Preserve immutable source snapshots/voice tokens through queued delivery and note edits. No source snapshot pointer escapes its lease. Split the current Take-wide velocity transformation from source reading: `LoopTake.cpp:2392-2397` currently applies Take master UnmutedLevel before delivery. Fan out raw source velocity/provenance, retain that legacy velocity scale only for Station destinations, and let Take/Loop destinations use raw velocity plus their existing audible audio-bus gains once. A destination-local stack event value for an intentional velocity transform is permitted; do not change shared source bytes. Otherwise child recorded instruments receive both velocity/timbre scaling and the same Take gain again.
5. Drain per-destination scheduled events and release retries, then render audio leaves, sum into Take, process Take rack, sum into Station, process Station rack, then apply existing final mix/export policy. MIDI begins and dispatches before any relevant rack renders. Finish processed-block receipts/recovery after each processor's render, including skipped/bypassed chains. Automation must retain its existing same-block ordering; inspect and test it when moving the MIDI phase.
6. Bounce is not a second live render. Preserve current bounce/source-capture coordinates, never redrain live ingress or reread MidiLoops from nested bounce WriteBlock calls. Initially preserve current audio-only bounce behavior; any offline MIDI instrument export is separate scope. Use an explicit render context/mode so nested bounce cannot accidentally consume a block twice.

For a pure MIDI Take, prepare an output bus and mixers using the existing supported rack/bus format, independent of recorded audio-channel count. Zero it, render instruments and tails every admitted block, then mix through Take/Station normally. Do not create dummy audio Loops or fake recording buffers. Decouple output bus width from capture stream count in publication, UI/export and latency code. Existing mono audio Loop racks retain their supported mono hosted layout; do not silently change layouts. A leaf with a rack must be able to process a zero-filled block for admitted live notes/releases/tails when source reads yield zero; respect capture activation, mute and lifecycle guards and test the zero-length case. Lack of audio material must not suppress cleanup. Unsupported layouts remain explicit failures/recoverable inactive slots.

## Latency and lifecycle invariants

Recorded event destination delay is `reference latency - destination-to-output path latency`, validated before publication with existing arithmetic/capacity limits. For Station this is its rack suffix; for Take it is Take suffix plus Station effect-path latency; for Loop it is Loop suffix plus Take and Station effect-path latency. A suffix includes the injected plugin and subsequent effects, excluding subsequent additive instruments; ancestor audio paths exclude Instrument roles (`vst/VstChain.cpp:50-74`). Include generator paths in longest-path discovery even for pure MIDI takes. Move the recorded audio source PlaybackDelay to the material path before the leaf rack, with delay `reference - complete audio-source effect path`; keep bounce/source capture outside it. Child instrument output then joins the already aligned material at its injection slot, using only its MIDI event delay, and is never passed through the old post-rack leaf delay. This avoids compensating generated output twice. Prepare the required buffers off callback and test this placement with source audio and instruments together before landing it; an instrument inserted late in a chain does not inherit upstream plugin latency for its own generated signal.

Live delivery remains immediate, with natural plugin/ancestor processing latency and no recorded-event compensation. Preserve non-realtime flags and original source/device mapping for recorded delivery. Reorder/latency changes use existing compensation epochs, invalidate obsolete queued attacks and release owned voices before resuming; infeasible preparation leaves a coherent prior/explicitly suspended configuration, not a half-applied topology. Respect per-entity anchors and rational MIDI quantization (`doc/loop-alignment-and-ninjam-sync.md`); this work does not change transport authority or stretch algorithms.

Retain per-destination live held notes/pedal state and per-(source,destination) recorded articulation ownership. A local mask/cable edit releases only that owner's retired permissions. A sibling/child using the same pitch/channel keeps sounding. Physical source loss releases contributions from that source across all destinations while preserving healthy-device ownership. Do not fan owner-synthetic note-offs into raw input. Disable/re-enable and remove/re-add between observed blocks must retain retirement history so skipped publications cannot resurrect queued attacks.

Carry existing bounded retry behavior through saturation, partial note/pedal release acceptance, bypass/resume, processor-block rejection, note edits, mute/audition, source replacement/ditch, owner deletion and plugin replacement. Retired chains/bindings stay pinned until scheduled events, accepted release receipts and reader leases permit collection. Collect and UI-thread destruction remain off callback; shutdown stops readers and performs existing quiescent final-release behavior. Never recover by panicking an unrelated surviving rack.
