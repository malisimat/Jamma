# Add and remove stations

## Scope and interaction

Add runtime management of local Stations, preserving the Station -> LoopTake -> Loop ownership hierarchy defined in [glossary.md](glossary.md). This document is an implementation plan; no feature code is included.

- Show a large plus button one station spacing left of the first local station and right of the last local station, centred where the added station would appear. Left inserts at the beginning; right appends. Project both anchors through the same layout/camera transform as stations and give them generous hit targets. Reveal these endpoints when navigating the layout; do not silently clamp an offscreen button onto another station.
- While Ctrl is held, show a bin icon on each removable local station. Release Ctrl to hide bins and cancel unfinished bin presses. Reset modifier/pressed state on focus loss.
- Clicking a bin removes an empty station without confirmation. For a nonempty station, show a modal popup naming the station and explaining that its takes and station configuration will be removed, with **Cancel** and **Delete station** buttons. Cancel is the default; Escape cancels. Releasing Ctrl after opening the popup does not dismiss it.
- Management controls consume their clicks so they cannot also select, record, drag, or change quantisation. Disable them while another modal, conflicting editor, or membership transaction owns input.
- Remote NINJAM stations remain connection-owned and have no user bin. Endpoint placement uses the local-station order, without changing remote membership.
- Add **Save rig as default...** to the GUI main panel. It opens a filename dialog rooted in `%APPDATA%\Jamma` (Roaming/Jamma). Only this explicit action saves the current rig and changes the startup default; subsequent performance edits remain in memory.

Keep at least one local station; while Ctrl is held, show its final bin disabled. A station is nonempty exactly when it owns at least one LoopTake, including a blank or currently recording take. Plugins, routing, names and other settings alone do not require confirmation. Permit deletion during recording, overdub, punch and queued trigger work: cancel the target's work through its owners as part of removal. There is no automatic retry or undo.

## Agreed behaviour

These choices are user requirements. "Immediate" means prompt feedback and asynchronous processing at the next safe boundary, not synchronous destruction from the click handler.

| Decision | Required behaviour | Implication |
| --- | --- | --- |
| Final local station | Keep one; show its bin disabled while Ctrl is held. | Failed-load recovery into a usable single-station session is a separate follow-up; runtime deletion does not change loader failure handling. |
| Confirmation | Confirm if and only if at least one take exists. | Plugins and configuration are discarded without an extra prompt. One confirmation covers deletion of the entire station, including its active recording. |
| Active or queued work | Accept deletion and cancel target work deterministically; never automatically retry a failed request. | Active recording is not a busy rejection. Late actions/results must not recreate content or reach a replacement station. |
| New station | Blank and unbound, with normal station defaults; no adjacent configuration cloning or automatic trigger creation. | Copying routes can unexpectedly duplicate capture or live MIDI. Specify allowed MIDI channels separately. |
| Deleted master with surviving content | Detach its reference while preserving tempo, grid and playback phase. | Do not make an unrelated survivor the new master or disturb a performance. Requires an owner-safe detach operation, not a broad timing clear. |
| Selection/camera | Reveal additions without selecting them. Preserve selections on surviving objects; remove selections in the deleted hierarchy, without choosing a neighbour. | If the deleted hierarchy contained the only selection, nothing remains selected. Move the camera only enough to reveal an addition; deletion causes no automatic focus jump. |

Keep this addition narrow: endpoint insertion/deletion and explicit saving of the current rig as default, one membership transaction at a time. No drag reordering, undo system, automatic rebinding, or new general transaction framework. Do not drop the coherent audio/input transition or lifetime checks to achieve that simplicity.

Rig persistence is explicit: station, trigger, routing and rig-setting edits during performance never automatically rewrite the loaded/default rig. Saving a default captures the complete current rig, rather than a delta or the originally loaded configuration. New unbound stations accepting MIDI channel 1, saved explicitly, remains a proposed default to settle before implementation.

Rig and session formats remain distinct: the current `RigFile` stores rig name/version, user settings and trigger/source/target configuration; station order/configuration, takes and loop material belong to `JamFile`. "Complete current rig" includes every current rig field, not recorded performances. Reuse the current load/save formats and startup selection. Do not add embedded rigs, new sidecars, schema migrations or automatic session/profile pairing for this feature. Saving a Jam continues to save Jam state; saving the rig explicitly stores the current bindings. Verify existing combined load behaviour and describe its limits rather than expanding persistence scope.

## Implementation boundaries

Make surgical additions to existing classes. No broad Scene extraction, replacement persistence framework, general transaction system or new thread is required. A small focused helper is appropriate only where it keeps genuinely new behaviour out of Scene.

| Responsibility | Owner and change boundary |
| --- | --- |
| Membership request/confirmation state | A small JammaLib station-management controller owns the new request state and validation. Scene wires it to existing membership, layout and lifecycle operations through explicit methods; it does not accumulate another large state machine. Do not move unrelated existing Scene behaviour. |
| Inventory and route candidate | Extend `RigCoordinator` narrowly to accept a candidate inventory and preserve receiver identity. Reuse its publication/acknowledgement flow. |
| Active-work cancellation | `Trigger`, Station/take owners and input subsystem handle their own commands and note cleanup; AudioHost applies the bounded boundary handoff. |
| Controls and presentation | `GuiMainPanel` owns the save button; station-control GUI code owns plus/bin drawing and hit testing. Reuse existing popup, camera and input routing. |
| Rig capture | `RigCoordinator` exposes committed rig configuration; the owner of current user settings supplies a value copy. Scene only forwards the request/result and existing wiring. |
| File save and startup defaults | A focused app-side rig-save helper owns the existing write helpers and current `InitFile` state. Main wires it to GUI and shutdown. Keep filenames, file I/O and defaults-update logic out of Scene and the engine coordinator. |

Keep the save flow to filename/overwrite confirmation, capture, rig write, defaults write and result. Reuse the existing job/UI execution path and atomic file helper. Ordinary repeat of the save action is enough after failure; no persistent retry journal, rollback framework or recovery workflow.

## Implementation sequence

1. **Define controller-owned requests and validation.** Keep new request/confirmation state in the focused station-management controller, with Scene providing thin wiring. Use target identity plus a membership revision for remove requests and popup callbacks, never a saved vector index alone. Serialize membership writers on the existing job/orchestration path. Validate current membership, local ownership, take presence and the last-local-station invariant. An empty, unconfirmed request that gains a take before input is closed requires confirmation. Once confirmed, consent covers the same station's complete hierarchy, including recording progress and new takes; do not repeatedly prompt as recording advances. A disappeared target or replaced session cancels the request. Cancel/Escape before acceptance has no effect on recording or membership. Show pending feedback and disable repeated management actions after acceptance.

2. **Prepare additions off callback.** Construct a Station using existing initialization for receiver, logging, clock, transport offset, buffers, channel counts, selection depth, and MIDI quantisation. Choose a unique display name and explicit channel/MIDI defaults; do not change existing stations' MIDI assignments when prepending. Persist explicit allowed MIDI channels so reload cannot recalculate them from the new index. Prepare resources on their required graphics thread before exposing drawable controls. Respect the existing persisted-local-station ceiling (`io::JamFile::MaxStations`, currently 256); a lower runtime limit requires a measured reason and a policy for larger existing sessions. This serialization ceiling is not evidence of callback performance. Remote connections keep their existing independent admission policy.

3. **Prepare one coherent topology change.** Build candidate ordered membership and remap surviving routes to the same Station identities. Clear routes targeting a deleted station and report affected bindings without an extra confirmation. Do not automatically retarget to a neighbour. Extend the coordinator's inventory-update path because current rig edits assume fixed station inventory/order. Reuse the existing input-close, audio-boundary acceptance, and acknowledgement protocol (`Scene.cpp:2074-2126`), extending it for active-target cancellation rather than inheriting routing-edit busy rejection. Prepare and validate fallible resources and routing before destructive cancellation starts. Separate station and rig publications alone do not guarantee coherence: establish and test their transition ordering so no reader combines incompatible inventories/routes. Keep the operation pending until the required acknowledgements arrive.

   **Cancel removed-target work through its owners.** After consent and candidate validation, gate relevant input and mark the target unavailable for new job/UI structural actions. At the audio boundary, stop its capture/playback participation and invalidate its delayed record/overdub/punch/ditch actions, pending completions and held-input state. Reuse existing cancellation/sequence mechanisms where suitable; do not call the broad `Trigger::Reset` concurrently with live readers. Extend `CanApplyCaptureRouting`/replacement handling only for the explicit removal path; ordinary rig edits retain their guards. Unchanged receiver identities must not become busy merely because their indices move.

   Drain or cancel queued job commands and acknowledge in-flight work on the owning thread. Tag/check removed-target identity and cancellation generation before attaching results; discard stale results off callback. A command that already owns the outgoing hierarchy may finish cancellation while that hierarchy remains retained, but cannot publish it back into the Scene. Clear deleted-take references from trigger histories as well as current receivers. Held trigger releases must not fire against a later binding; require a fresh activation. Release held MIDI notes through existing owner-thread paths. Structural cleanup and plugin/resource destruction remain off callback. If the stream is stopped, use the established quiescent application path rather than waiting forever for a callback.

   Preserve trigger IDs and source configuration when unbinding a deleted target. Set `StationTarget` to an explicitly empty string: an absent target invokes legacy index resolution (`RigFile.cpp:650-673`) and can silently bind to a different station. Normalize legacy targets against the old inventory before changing order. Compare old/new receiver identity, not just `StationIndex`: deletion can replace the Station at an unchanged index. The current `ReceiverChanged` calculation in `RigCoordinator.cpp` assumes fixed inventory and must be corrected for membership edits.

4. **Commit UI state and retire safely.** Recompute station positions, camera observations, endpoint anchors, and indices. Preserve selection by surviving object identity, reveal additions without selecting them, and clear selections only within the removed hierarchy. Clear its hover/pressed paths, editor targets, quantisation hints, plugin editor references and pending commands; never redirect them to an index occupant. Close affected editors through their owner threads. Detach a deleted master Loop reference while preserving tempo, grid and playback phase when local content survives; do not promote another loop. If no local content remains, follow the existing empty-content timing policy, retaining remote timing when its authority is active. Consult [loop-alignment-and-ninjam-sync.md](loop-alignment-and-ninjam-sync.md) before timing edits. Keep outgoing Stations and processor state alive until audio/input leases, job work and cancellation acknowledgements permit retirement; unload plugins and release graphics resources on the appropriate non-audio threads.

5. **Integrate controls and existing saving.** Reuse `GuiButton`, `GuiPopup`, and popup routing. Add plus/bin art to `Jamma/resources/ResourceList.txt` using the tga-icon-gen skill when implementing new control art. Existing Jam save/export captures committed membership, order and station descriptors; explicit rig save captures remapped bindings. Exclude pending operations and keep current file formats. Verify loading the saved Jam with the explicitly saved rig reproduces station configuration and bindings.

   Decouple runtime acceptance from disk persistence: `RigCoordinator::CompleteTransition` currently requires the rig-save callback before pending publication. Remove automatic disk writes from performance-time membership and rig edits while preserving their validation and acknowledgement protocol. Disk availability must not govern runtime edit acceptance. Audit all `_saveRig`/`SaveRig` callers, including rig-settings changes; saving a default must not install a callback that resumes autosaving later edits. Preserve necessary first-run generated-file publication as a distinct startup path.

   Disable save actions during a membership/rig transition so capture uses committed state. Do not introduce a queued-save mechanism or redesign session persistence. Retain the current loader and first-run behaviour.

6. **Save the current rig as the startup default explicitly.** The app-side rig-save helper handles the filename dialog, paths and defaults storage; engine/settings owners supply a complete, owner-safe value of the committed rig. Use the existing GUI input ownership for the main-panel button and dialog. Cancel performs no writes. Disable the button during topology/rig transitions or another save. While the dialog owns input, prevent conflicting local edits. Recheck transition state after filename/overwrite confirmation; if busy, return a concise busy result and allow a fresh click. Capture committed rig fields and current user settings on their owner path, then pass a value to off-callback serialization. Subsequent edits cannot change that captured value.

   Accept a filename within `%APPDATA%\Jamma`, using the existing rig JSON convention. Reject traversal and reserved `defaults.json`/temporary-file collisions; create the directory if needed. Confirm replacing an existing rig file. Write the entire rig using the existing temp-write, flush and replace helper (`SaveRigAtomic`), never by modifying the loaded profile implicitly.

   **Save ordering:** first publish the selected rig file successfully, then atomically replace `defaults.json` with its rig path and appropriate user-selected origin/load policy. Preserve the current Jam selection, window placement, logging and other defaults fields. Honour the existing `JAMMA_DEFAULTS_PATH` override for the active defaults file; normal operation uses Roaming/Jamma/defaults.json. Serialize defaults writers and update the app's in-memory defaults only after the defaults write succeeds, so shutdown cannot restore the old rig path.

   If rig saving fails, leave defaults untouched and report failure. If defaults saving fails after the rig succeeds, keep the saved rig and report **Rig saved; startup default unchanged**. The user can repeat the save action; no separate retry state is needed. Report full success only after both steps succeed. Two separate atomic replacements are not a crash-atomic pair; do not add rollback machinery. After success, later performance edits still require another explicit save.

## Thread safety and real-time constraints

For every new shared field, document its owner thread, readers/writers, synchronization, and teardown path. Scene remains orchestration; engine/audio behavior stays in JammaLib and its existing owners.

Apply this to every new access, including GUI callbacks, dialog completion, rig capture and shutdown. Keep controller request state on the existing job/UI owner; marshal callbacks from other threads onto that path. Protect GUI state with existing rendering/input synchronization. `RigCoordinator` candidate inventory is writer-owned; readers receive immutable committed publications. Capture user settings on their owner thread or under their existing off-callback synchronization; never traverse mutable Stations/triggers from the file writer. The app-side save helper has one serialized owner for `InitFile`, save-in-progress state and defaults writes, including shutdown window-placement updates. Return results to GUI through its owner path. Stop/drain requests before destroying controller/helper targets; callbacks cannot retain a dangling Scene, panel or app reference.

Use the established published immutable snapshot pattern. Never mutate published topology while a lease references it. Snapshot lifetime protection does not make Station processor state safe for concurrent mutation. Callback-owned state changes must use existing bounded handoff/boundary mechanisms.

No allocation/deallocation, vector growth, Station construction/destruction, locks, waits, exceptions, plugin unloads, popup work, formatted logging, or I/O on the audio hot path. Keep snapshot store/exchange/load/collect off callback; serialize writers and pump retirement even when no more edits occur. Preserve bounded borrow failure behavior and distinguish it from a valid empty publication. Never call locked `SnapshotStations()` from callback. Stop readers and release leases before destroying publishers.

Define lock ordering for non-audio work; avoid recursive scene-lock acquisition and avoid holding it across plugin/resource preparation or acknowledgement waits. Prevent races among double-clicks, popup confirmation, input dispatch, network updates, save/export, focus loss, and shutdown. The station limit and transition work must preserve a predictable callback workload.

Recording that starts after a popup opens is covered by confirmed deletion of that station; it is cancelled at the acceptance boundary rather than causing rejection. Close/drain relevant input before cancellation, and prevent a job action from attaching new content after the final unconfirmed-empty check. Keep playback and pending work on surviving stations running. Cancel stale requests rather than redirecting them to an index occupant. Unrelated remote membership changes may require rebuilding the candidate without changing the target or prompting again for that same confirmed hierarchy.

Prefer existing Station object identity plus revision for in-session requests; do not introduce a persisted GUID/schema migration solely for popup targeting. Serialized routing currently uses station names, so name uniqueness and legacy ambiguous-name handling must be tested separately. No callback may drop the last owner of a removed Station, plugin, trigger receiver, or master Loop.

## Logging and error handling

Log structured, low-volume events on the job/UI side: request, confirmation/cancel, validation rejection, prepared revision, audio/input acceptance, completion, and retirement. Include operation ID, station identity/name, old/new order or count, topology/rig revision, reason, and affected binding count. Follow existing logging configuration. Audio diagnostics use bounded counters/receipts read and formatted off callback.

Handle construction/resource failures, capacity limits, conflicting transactions, stale targets, rejected routing candidates, shutdown and delayed acknowledgements explicitly. Active work on the removed target is cancellation work, not a busy rejection. Before destructive cancellation begins, discard failed candidates and retain committed state. Once cancellation or publication starts, use a defined completion/recovery path; do not claim the recording can be restored or blindly reverse a partially accepted transition. Never free possibly referenced objects. Keep pending management actions disabled, show a concise actionable error and allow a fresh request after safe recovery. User cancellation before acceptance has no membership or recording effect. A delayed acknowledgement is not permission to free the outgoing hierarchy or abandon retirement pumping.

## Validation and completion criteria

- Native tests cover prepend/append defaults and order; empty deletion; confirmation/cancel; last-local and remote guards; deletion during recording, overdub and punch; stale popup/repeated requests. Plugins/routing/settings alone must not prompt, while blank and recording takes must.
- Extend `RigSnapshot_Tests.cpp` and `SceneRoutingIntegration_Tests.cpp` for index shifts, deleted bindings, MIDI dispatch, and transitions already in progress.
- Include same-index/different-receiver replacement, legacy absent versus explicitly empty route targets, and delete-then-add without accidental rebinding. Verify retained trigger/source settings and explicit MIDI channels survive reload.
- Race recording start and take creation against confirmation, the unconfirmed-empty check and boundary acceptance. Verify one confirmation covers ongoing recording, repeated clicks produce exactly one operation, and failed deletion never retries automatically.
- Cover delayed/quantised actions, queued structural commands, in-flight job results, held trigger releases, trigger histories and held MIDI notes. After cancellation, none may restore the deleted hierarchy or affect a newly added station. Exercise stopped-stream application and unaffected active work on surviving stations.
- Verify snapshot lifetime during concurrent publication/removal, delayed readers, bounded read failure, retirement without further edits, and shutdown. Extend the allocation probes in `AudioFlow_Tests.cpp` for playback during edits.
- Test master-owning station removal, last local content removal with/without NINJAM, and save/reload of membership plus bindings.
- Test save disabling/revalidation during transitions; a reusable rig profile must follow the agreed persistence policy. Verify existing Jam plus explicitly saved rig loading without introducing a new persistence format.
- Verify station, trigger, routing and user-setting edits leave loaded/default rig files byte-identical until explicit saving. Runtime edits must succeed without a writable rig file.
- Verify the main-panel save writes all current rig fields, prompts for overwrite, handles cancel/invalid filenames, and updates only the intended defaults fields after rig publication. Reload the chosen default and compare its complete rig configuration with the captured value.
- Inject rig-write and defaults-write failures separately; test repeating the save action, edits during file I/O, dialog/transition overlap, serialized defaults writers and shutdown after a successful new default selection. Verify subsequent edits do not autosave. Exercise `JAMMA_DEFAULTS_PATH` isolation.
- Review class boundaries: Scene contains thin delegation/wiring, persistence stays app-side, and cancellation stays with engine/input owners. Audit all new reads/writes and teardown callbacks for the documented owner/synchronization; passing a snapshot must not mask unsynchronized mutable-object access.
- Manually check projected endpoint placement and generous hit targets across view modes, camera movement and resizing; reveal additions without selecting them; preserve surviving multi-selection and leave no selection when its only target is deleted. Check Ctrl quantisation coexistence, focus loss, modal input ownership, pending feedback and plugin/resource cleanup.
- Before each build or native-test run, read the worktree's local `.vscode/tasks.json`; follow [build.md](build.md) for incremental affected-project builds and relevant native tests. Run the threading-review audit and inspect callback bodies after implementation.

Complete when UI behavior, route identity, persistence, and lifetime tests pass and the hot-path review finds no new allocation, blocking, logging, or race regressions. No builds are required for this documentation-only change.
